# ide：IDE 选区注入

复用本机已安装的 **Claude Code IDE 插件**（JetBrains / VS Code 系），把编辑器里选中的文本作为上下文自动附加到下一条 pi 消息。不写任何 IDE 侧代码。

## 工作原理

Claude Code 的 IDE 插件本身是一个常驻的 MCP over WebSocket 服务：

1. 插件为每个已打开的项目写 `~/.claude/ide/<port>.lock`（文件名即端口，内容含 `authToken` 与 `workspaceFolders`）；
2. 客户端按 `workspaceFolders` 覆盖 pi `cwd` 选出目标 lock，连 `ws://127.0.0.1:<port>`，认证走 `X-Claude-Code-Ide-Authorization` 头；
3. `initialize` 之后插件主动推送 `selection_changed`（选中文本全文、文件路径、行范围），**必须**应答它每约 5 秒一次的 `ping` 请求。

选区文本来自 IDE 内存 Document，**未保存的改动也包含在内**，比"发文件引用让模型自己读磁盘"更可靠。

## 使用

在 IDE 里选中一段代码，切到 pi 直接提问即可：

- 选区保留 `<ide_selection file="…" lines="…">` 格式，以 `customType: "ide_selection"`、`display: true` 的独立消息显示并提供给模型；用户输入保持原样，**发送后自动清空**，等待下一次选中（自动跟随 + 一次性消费，不会重复附加）；
- 有选区时通过 `setStatus("ide", "⧉ 路径:行范围 · N 行")` 提示，由 footer 渲染方独立成行展示（见下「展示契约」）；连接异常时显示 `IDE ✗ …`，无提示时 footer 不占用。未发现匹配当前目录的插件（在 IDE 外跑 pi 的常态）不占 footer，只在 `/ide status` 详情里体现。
- 选区的含义与使用边界已写进系统提示词告知模型（见下「提示词契约」），对用户不可见。

命令与开关：

| 入口 | 作用 |
| --- | --- |
| `/ide status` | 连接状态、插件版本、待注入选区、提示词 section 挂载态 |
| `/ide on` / `/ide off` | 会话内开关（不持久化，重启恢复） |
| `/ide clear` | 丢弃当前待注入的选区 |
| `/ide reconnect` | 重连（IDE 重启换端口后用） |
| `pi --no-ide-selection` | 启动时禁用 |
| `PI_IDE_SELECTION=0` | 环境变量方式禁用 |

护栏：选区超过 400 行 / 32KB 截断（`selection.ts` 的 `DEFAULT_LIMITS`）；用户文本已含同段文本时跳过注入；扩展自身注入的消息不会被再次附加。

## 提示词契约（`prompt.ts`）

自动注入的选区需要解释，否则模型会把「存在 `<ide_selection>` 块」默认读成「用户想处理这段代码」。扩展在 `before_agent_start` 向 `event.systemPromptOptions.sections` 贡献一个固定 section（`ide_context`），说明：

- 块内文本取自 IDE 内存，可能含未保存改动，与磁盘不一致；据此下结论或改代码前先用 `read` 核对；
- **相关性不确定**：用户可能是刻意给上下文，也可能是随手选中、切走前忘记取消，甚至误选；
- 相关性以用户问题为准，判定无关时直接忽略，不复述也不点评这段代码；
- 选区只对一起提供的那条用户问题有效，历史记录中的选区不会自动删除。

实现要点：

- 走 section 通道而非返回整段 `systemPrompt`：Pi 只对变化的 section 增量下发一条 system 更新，固定文案整个会话只生效一次；返回 `systemPrompt` 会转成 `forceSystemPrompt` 整段替换，每次变更都是 prompt cache miss。
- section 名不取 `ide_selection`：Pi 会把 section 正文自动包成 `<section名>` 标签，同名会让模型把「说明」误读成「这里有一段选区」。
- 仅在 ide 启用时贡献；`/ide off` 或 `--no-ide-selection` 后不再贡献，section diff 会把它撤销。
- `input` 消费选区后调用 `sendMessage`，不改写用户输入；空闲时以 `triggerTurn: false` 先追加选区，再由用户输入启动请求；生成过程中先将选区放入与用户输入相同的 `steer` / `followUp` 队列。两种路径均按「选区 → 用户问题」提供，不使用会将选区放到问题后的 `nextTurn`。
- 选区使用自定义渲染器，沿用 Pi 默认背景，左右间距跟随 `outputPad`；单行标题为 `IDE 选区 · 路径:行号`（多行选区显示行范围），路径优先相对发送时的工作目录，其次相对 HOME；不另列路径。正文直接显示代码；不超过 80 行且不超过 8,192 字符时按文件类型高亮，超过任一阈值则保留纯文本，不显示包装 XML；标题不随系统或终端语言切换。窄终端从左侧省略过长路径，尽量保留文件名和行号，不换行。模型正文仍保留绝对路径与 XML，界面通过 `details` 读取经相同截断的数据。`customType` 不会传给模型，模型通过正文的 XML 标签识别选区。
- **固定说明对用户透明**：section 以 system 消息承载，而交互模式对 `role === "system"` 不渲染任何内容（`interactive-mode.ts` 的 `case "system": break;`），不会在对话里多出一块可读文本；但该消息仍会写入会话记录，恢复会话时随历史回放。
- **不会每轮重发**：下一轮的「已有 section」由 `getCurrentSystemMessage()` 折叠全部 system 消息得到，因此首轮下发后 diff 为空；实测渲染与 diff 可直接调 `dist/core/system-prompt.js` 的 `buildSystemPromptSections()` / `diffSystemPromptSections()` 复现（本机 0.86.1 与 0.87.0 产物均有该入参）。

自查：`/ide status` 末行显示 `提示词: ide_context 已挂载`（ide 关闭时显示未挂载）。

## 已知限制

- 旧会话的选区消息没有结构化 `details`，回退到 Pi 默认视图并显示原 XML，不从可能包含 XML 的代码正文反向解析。过长路径在标题中省略，极窄终端可能连文件名也无法完整显示；完整路径始终保留在会话 XML 中。

- 选区和用户问题是两条独立消息，宿主没有提供将两者原子入队的接口。生成过程中若使用 `one-at-a-time` 队列，或模型循环恰好在两次入队之间取队列，可能先单独处理选区；`all` 模式通常会一起取出，但不构成原子性保证。本扩展不修改全局队列模式，也不合并正文，以保留独立展示与用户原始输入。
- 选区在 `input` 阶段即被消费并追加或入队。如果后续扩展拦截输入，或请求在模型、认证等校验阶段失败，选区可能已进入会话而对应问题尚未发送；清除待发送队列也不保证同时清除独立的选区消息。当前未实现跨消息回滚，避免依赖宿主内部会话和队列状态。
- 「选区只服务当前问题」是提示词约定，已发送的选区仍保留在会话历史中，不会自动过期或删除。

## 展示契约（跨扩展）

连接与待发送选区提示只产出状态文本（`setStatus`），不自带 footer 视图。发送后的选区使用保留 Pi 默认样式的中文标题消息视图。Pi 默认 footer 会自动渲染扩展状态；若使用自定义 `statusline` 自定义 footer，由它负责把每个扩展状态独立成行、左截断保留尾部（文件名/行范围是识别信息）并用 `mdLink` 着色（对齐 Claude Code 的 ide 提示色）。statusline 不理解选区语义，ide 也不依赖 statusline 存在——删掉任一边另一边仍正常工作。

### 依赖的终端设置：clearOnShrink

提示行出现/消失会让 footer 在 1~2 行间变化。pi-tui 差分渲染默认**不清除内容收缩后的残留空行**（`terminal.clearOnShrink` 默认 `false`，为减少慢终端重绘），表现为：取消选区后 `⧉` 行没了但留一行空白，直到下次按键才消失。

如遇到残留空行，可在 `~/.pi/agent/settings.json` 启用：

```json
{ "terminal": { "clearOnShrink": true } }
```

注意：该设置**只在 pi 启动时读取**，改完必须完全退出重开，`/reload` 无效。换机器/重装后若再现“取消选区残留空行”，先查这个设置。

## 模块结构

| 文件 | 关注点 |
| --- | --- |
| `index.ts` | Pi 装配层：事件、命令、footer 状态应用（薄，无业务决策） |
| `state.ts` | 会话状态机：武装/一次性消费/视图快照（含 footer 哪些情况该占位，纯逻辑可单测） |
| `client.ts` | WebSocket 传输与断线退避重连 |
| `protocol.ts` | JSON-RPC 编解码，**唯一**存放未公开协议知识的地方 |
| `lock.ts` | lock 文件发现与按 cwd 选路（只读，不删他人 lock） |
| `selection.ts` | 选区模型与呈现：footer 摘要、注入块、截断 |
| `render.ts` | 选区消息视图与固定中文标题，模型正文保持原样 |
| `prompt.ts` | 系统提示词 section：说明 `<ide_selection>` 块的来源与使用边界 |

## 依赖说明

本扩展依赖 [`ws`](https://www.npmjs.com/package/ws)：认证只能通过自定义请求头传递，Node 内置 WebSocket 不支持自定义头（实测 header 被静默忽略，服务端以 1008 拒绝）。这是本包的运行时第三方依赖，pi 以 git 包安装时会通过 `npm install --omit=dev` 装入。

## 协议实测要点（JetBrains 插件 0.1.14-beta，全部来自本机一手验证）

- 握手只需标准 `initialize`；服务端**不认识** `notifications/initialized`（返回 -32601），不要发。
- 选区没有对应 tool，**只能靠 `selection_changed` 通知**；`initialize` 完成后无需订阅，推送自动开始（含切换标签页时补推当前状态）。
- 载荷行号 **0-based、`end` 排他**；纯光标移动也会推（无 `text`），必须过滤，否则状态提示会被高频刷屏。
- 插件每约 5s 发 `ping` 请求，必须回 `result: {}`；不应答约 3s 后它用 `notifications/cancelled` 清理请求，长连接不稳。
- 多客户端可同时连接：本扩展与正在运行的 Claude Code 会话共存无冲突，从协议看两者地位等同。
- 认证失败的表现：连接建立后立即被 `1008 Invalid or missing authentication token` 关闭（JetBrains 侧只读 header，无 query 参数兑底，已从插件字节码确认）。
- 插件对每个已打开项目各写一个 lock，同一 IDE 进程共享 pid、端口独立；选错端口会拿到别的项目的选区，所以匹配不到时宁可不连。
- `ide_connected` 通知不是接收推送的前提，本扩展不发送（它只用于插件侧配置终端）。

## 设计取舍

- **自动跟随 vs Claude Code 的显式触发**：CC 靠 IDE 里「Add to Claude Code」插 `@file#L10-20` 引用、提交时读磁盘；本扩展自动跟随选区、用推送里的内存态全文。代价是每条消息带选区 token，收益是未保存改动也能被看到、无额外读盘往返。
- **一次性消费**：发送后必须重新选中才再注入，避免同一段选区粘在后续所有消息上。
- **提示形态的坑结论（按渲染模式区分）**：不用 `setWidget` 附件条。它的代价取决于 `ui.tuiMode`：regular下 widget 行位于输入框上方，会把输入框整体下推；fullscreen 下反而不推输入框（由 transcript 吸收），而 footer 多一行会上推输入框。在 regular 模式下， `setStatus` + footer 更温和（CC 也是同款：通知行、左对齐、超宽截断、muted blue）。切换渲染模式后可重新评估，
- **XML 标签而非代码围栏**：选中文本可能含 ``` 或 `----`，围栏会被提前逃逸。

## 排障

| 现象 | 处理 |
| --- | --- |
| `/ide status` 显示未发现匹配 lock | 在 IDE 外跑 pi 的常态，不占 footer；在 IDE 里打开 pi cwd 所在项目（确认 Claude Code 插件已装且 IDE 已重启过）后执行 `/ide reconnect` |
| footer 出现 `IDE ✗ …` 持续重连 | IDE 重启换端口，`/ide reconnect`；仍不行看 `~/.claude/ide/` 下 lock 的 pid 是否存活 |
| 发了消息但模型说没看到选区 | 确认发送前 footer 有 `⧉` 行；`/ide clear` 后重新选中再发 |
| 模型把无关选区当成任务、擅自改动选中代码 | `/ide status` 看「提示词」行是否已挂载；若为未挂载说明 ide 已关闭，`/ide on` 后恢复 |
| 取消选区后残留空行 | `terminal.clearOnShrink` 未生效，见上文，改完必须重启 pi |
| 验证链路本身 | 检查匹配 lock、插件版本与 WebSocket 连接状态（`/ide status`） |

## 边界与已知限制

- 协议是 Anthropic 未公开的内部实现，插件升级可能变更；`protocol.ts` 集中容错（字段全 optional、坏报文降级为忽略），并可通过 `serverInfo.version` 观察版本。
- 任何能读 `~/.claude/ide/*.lock` 的本机进程都能获取你 IDE 里选中的文本——这是 Claude Code 插件的既成事实，不是本扩展引入的，接入前应当知情。
- VS Code 系（VS Code / Cursor / Windsurf 等）插件走同一协议（lock 同目录、同认证头、同 `selection_changed`），载荷多 `fileUrl` / `selection.isEmpty` 字段，解析层已按 optional 容错；但未在 VS Code 上实测。
- 仅按 `cwd ⊆ workspaceFolders` 匹配 lock；多个 IDE 项目同时覆盖同一 cwd 时取最长匹配。
